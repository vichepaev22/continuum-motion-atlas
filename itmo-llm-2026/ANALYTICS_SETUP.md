# Аналитика цифрового издания «За пределами языка»

**Состояние на 21.11.2026:** интерфейс и код интеграции опубликованы. **Внешняя аналитика ещё НЕ подключена**: нет сайта/персонального скрипта Plausible и подтверждённого решения оператора по обработке данных. Не путайте это с работающим счётчиком посетителей.

## Что уже реализовано

- Кнопка «Настройки аналитики и конфиденциальности» внизу издания.
- Отдельное модальное окно с описанием передаваемых данных и возможностью отзыва согласия.
- После настройки счётчика читатель сам принимает или отклоняет аналитику; без согласия на страницу **не загружается** сторонний аналитический JavaScript.
- Браузерный сигнал `Do Not Track` / `Global Privacy Control` блокирует передачу даже при ранее сохранённом разрешении.
- Разрешение хранится локально. Отзыв вызывает перезагрузку страницы, чтобы прекратить работу уже загруженного счётчика.
- События сайта `itmo:interaction` переводятся в Plausible только через фиксированный белый список: имена событий, номера моделей и стандартные категории задач.
- Нельзя передавать поисковый текст, ответы и комментарии моделей, произвольные промпты, версии модели, личные данные или экспортированный JSON.
- Тесты `tests/analytics.spec.js` проверяют отключённый счётчик, добровольное разрешение, удаление личного текста из события и полный отзыв.

## Подключить реальные показатели посетителей (владелец сайта)

1. Создайте проект для домена `vichepaev22.github.io` в **[Plausible Analytics](https://plausible.io/)**. Издание находится в каталоге `/continuum-motion-atlas/itmo-llm-2026/`, но счётчик устанавливается **только на страницы этого каталога**.
2. Откройте настройки проекта **General → Tracking → Review / Site Installation**. Получите **персональный URL скрипта** из вашего фрагмента установки, вида `https://plausible.io/js/pa-XXXXX.js`.
3. Проверьте территорию обработки данных, положения договора и правила обработки персональных данных для вашей аудитории; определите оператора данных, уведомление, срок хранения и правовое основание. При необходимости обновите текст политики. Этот документ — техническое описание, а не юридическое заключение.
4. Откройте файл [analytics-config.js](analytics-config.js) в GitHub и укажите персональный `siteScriptUrl` **вместо пустой строки**. После проверки условий поставьте `legalReady: true`. Идентификатор скрипта может быть публичным, но **никогда не вставляйте ключ доступа к API и секреты**.
5. GitHub Pages опубликует изменённый файл. Проверьте сайт в чистом браузере: до согласия запросов к `plausible.io` быть не должно; после согласия должен появиться персональный скрипт и сетевой запрос событий; после отзыва — больше никаких отправок.
6. В Plausible откройте **Goals**, создайте цели для нужных событий, перечисленных ниже. Посмотрите агрегированные посещения, открытия глав и конверсию в лабораторию по пути `/continuum-motion-atlas/itmo-llm-2026/`. При необходимости сопоставляйте с обычными pageviews.
7. Оценивать поведение **всех читателей** можно только после включения счётчика и накопления реального трафика. Технические проверки не заменяют наблюдений за людьми.

Актуальная документация разработчика: [Installation](https://plausible.io/docs/plausible-script), [New script (2025+)](https://plausible.io/docs/script-update-guide), [Custom events](https://plausible.io/docs/custom-event-goals).

### Важно: старая схема устарела

В октябре 2025 Plausible перешёл на персональный скрипт для каждого сайта. Универсальный путь `https://plausible.io/js/script.js` **не используется** в интеграции. Модуль вызывает `plausible.init()` согласно актуальному формату.

## Событийная модель для улучшения издания

| Цель / событие | Какой вопрос даёт изучить | Безопасные параметры |
|---|---|---|
| `Atlas · chapter_navigation` | Какие главы чаще открывают через навигацию? | `chapter` из фиксированного списка |
| `Atlas · search_open` | Нужен ли читателям поиск? | `source` |
| `Atlas · search_result_open` | Находят ли читатели нужные разделы? | `chapter`, `kind` |
| `Atlas · model_access_filter` | Выбирают онлайн-чат, веса или закрытые модели? | `value` |
| `Atlas · model_outbound` | Переходят ли к моделям из каталога? | `index` 0–15, `kind` |
| `Atlas · compare_models` | Используют ли сравнительную таблицу? | `a`, `b` 0–15 |
| `Atlas · training_stage_explain` | Насколько вовлекает схема обучения? | `step` 1–7 |
| `Atlas · lab_task_select` | Какие проверочные задания востребованы? | `task` из четырёх категорий |
| `Atlas · lab_result_saved` | Завершают ли читатели собственный тест? | `task`, `modelIndex` |
| `Atlas · lab_results_export` | Экспортируют ли результаты? | `count` 0–50 |
| `Atlas · share_issue` | Делятся ли выпуском? | нет |
| `Atlas · source_pdf_open` | Переходят ли к исследованию ИТМО? | нет |

**Не измеряем:** содержимое запроса, содержимое ответа, текст версии, локальные оценки и идентификаторы читателя.

## Как анализировать результаты без самообмана

- На первых 100–200 посещениях анализируйте прежде всего **работоспособность и наблюдаемые переходы**, а не объявляйте победителей на основе небольших различий.
- Отношение `lab_result_saved` к посещениям страницы лаборатории может подсказать, насколько понятен инструмент, но без идентификации пользователя это не строгая конверсия уникальных людей.
- Сравните интерес к главам и к лаборатории; высокий процент отказов может объясняться случайным внешним трафиком, а не плохим дизайном.
- Не считать число кликов доказательством понимания сложного материала. Для этого нужны задачи на понимание, опросы читателей и качественные интервью.
- После получения достаточных данных сначала сформулируйте **конкурирующие гипотезы**, затем выберите минимальную проверяемую правку интерфейса, а не меняйте одновременно всё.

## Автоматическая проверка

В `tests/analytics.spec.js` временно подменяется конфигурационный скрипт с тестовым `pa-test123.js` и имитируется ответ провайдера, не отправляя настоящие события. Проверяются:
- отсутствующая аналитика по умолчанию;
- наличие согласия перед загрузкой счётчика;
- **исключение пользовательского текста** из события `lab_result_saved`;
- запрет и отзыв согласия после перезагрузки.

Контрольная команда в каталоге проекта: `npm run test:e2e`. Реальную доступность Plausible и корректность кабинета владельца отдельно нужно проверить на живом сайте после регистрации.
