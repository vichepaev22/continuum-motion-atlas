# «За пределами языка» — релиз 2.0: методика и настройка аналитики

Дата обновления: **21 ноября 2026 года**. Владелец проекта: репозиторий `vichepaev22/continuum-motion-atlas`.

## Что включено сейчас

- 16 позиций каталога с различием между чатом, публичными весами и информационными ссылками. Реестр и типы доступа: [MODEL_ACCESS.md](MODEL_ACCESS.md), исходная проверка — 20.11.2026.
- Авторский визуальный разворот с каменным андроидом: `assets/editorial-stone-android.svg`.
- Лаборатория читателя: четыре одинаковых тестовых задания, ручной ввод ответов, собственные оценки от 1 до 5, локальное хранение максимум 50 записей, выгрузка JSON. **Не интеграция с API LLM, не бенчмарк и не коллективный рейтинг.**
- Интерактивная схема семи этапов из исследования. Табличные объёмы — ориентировочные диапазоны, не обещание результатов для конкретной модели.
- Playwright-тесты на desktop и mobile в `tests/v2.spec.js`.
- События интерфейса `itmo:interaction` с именем действия и ограниченными параметрами без текста ответов и самих промптов. По умолчанию события не передаются во внешний сервис.

## Протокол проверки 16 ссылок

1. Сопоставить модель и её версию с таблицами на стр. 9–11 оригинального отчёта ИТМО. Кнопка «Попробовать» должна вести в действительно доступный чат/демо, а не на страницу весов.
2. Проверить URL и HTTPS для каждого элемента [MODEL_ACCESS.md](MODEL_ACCESS.md). Статусы 403 и 429 из автоматического сканера могут означать блокировку бота, а не потерю доступа обычным пользователем — перепроверить вручную.
3. Сравнить опубликованную версию чата с названием модели: GigaChat и Алиса могут обновлять служебную модель, Saiga Nemo 12B — конкретная демоверсия, отличная от ранних Saiga. T-Pro демостенд может находиться в спящем режиме.
4. Указать дату и ссылку на подтверждение при каждой редакционной корректировке. Не рекламировать «точный тест» там, где версия не известна.
5. Не объявлять версию «закрытой навсегда»: достаточная формулировка — «прямой публичный тест не подтверждён».

## Подключение реальной аналитики — решение требуется отдельно

GitHub Pages — статический хостинг. Чтобы видеть посетителей, нужен внешний сборщик или сервер; **сейчас реальных агрегированных данных нет**.

Рекомендуемые альтернативы:
- **Яндекс Метрика** — привычные отчёты для русскоязычной аудитории, но нужно проверить обработку данных и настройки конфиденциальности.
- **Plausible или Matomo** — минимизация собираемых данных; проверить место обработки данных, договорные условия и фактическую конфигурацию.
- **GA4** — широкие аналитические возможности, но может потребовать более сложной настройки согласия, трансграничных передач и уведомлений.

### События без содержимого введённых ответов

| Событие | Допустимые параметры | Что нельзя передавать |
|---|---|---|
| `search_open` | расположение кнопки | поисковый текст |
| `model_access_open` | индекс позиции, тип ссылки | данные аккаунта |
| `lab_task_select` | фиксированная категория | введённый промпт |
| `lab_model_select` | числовой индекс | личные идентификаторы |
| `lab_prompt_copy` | категория | текст пользовательских запросов |
| `lab_result_saved` | категория, индекс модели | ответ модели, оценки и версия, если это свободный текст |
| `training_stage_explain` | номер 1–7 | произвольный текст |
| `lab_results_export` | количество | экспортированный JSON |

### Перед включением

1. Выбрать сервис и контролёра/оператора данных.
2. Определить законные основания обработки, политику конфиденциальности и применимые требования по согласию.
3. Добавить доступные пользователю настройки аналитики; не отправлять событие до допустимого основания обработки.
4. Проверить в браузере сетевые запросы: никакие поля из ответов лаборатории не должны уходить на аналитический endpoint.
5. Проверить отчёты на тестовом трафике и настроить срок хранения данных.
6. Только после этого публиковать код счётчика и идентификатор проекта (никогда не секретный API-ключ в публичном репозитории).

## Важные ограничения

Читательская лаборатория **не вызывает модели автоматически**, не собирает централизованный рейтинг и не гарантирует неизменность внешних демо. Записи в `localStorage` могут исчезнуть при очистке браузера; их можно скачать JSON. До подключения аналитики мы не можем достоверно утверждать, какие разделы наиболее популярны.

## Дополнение: приватная событийная аналитика (21.11.2026)

Опубликованы `analytics-config.js`, `analytics.js`, `analytics.css` и отдельные тесты `tests/analytics.spec.js`. Посетитель управляет согласием из футера; при подключённом счётчике появляется ненавязчивое предложение разрешить аналитику. До явного разрешения сторонний скрипт не загружается; при отзыве согласия страница перезагружается для выключения коллектора.

**Включение реального сбора по-прежнему ожидает действий владельца:** открыть проект Plausible, получить **персональный** URL скрипта `https://plausible.io/js/pa-XXXXX.js`, проверить правовые основания и настройку данных, внести адрес в `analytics-config.js` и только затем переключить `legalReady` на `true`. Старый универсальный `/js/script.js` в новом формате Plausible не используется.

Схема передаваемых событий — только известные названия и фиксированные категории; введённые промпты, текст ответов моделей и локальные пользовательские оценки исключены. Полная инструкция и KPI: [ANALYTICS_SETUP.md](ANALYTICS_SETUP.md). Браузерные тесты запрещают регрессии приватности. **Реальных данных о поведении аудитории пока нет**, поэтому делать выводы о предпочтениях читателей преждевременно.
